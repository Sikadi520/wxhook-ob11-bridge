# 安全与风险

这个项目做的事——把一个 DLL 注入微信进程——本身就意味着几层风险。用之前请逐条看完。

---

## 1. 封号风险

DLL 注入违反微信用户协议。腾讯有检测能力，什么时候收紧是它说了算。

**能做的**：

- **只用小号**。不要用主号，也不要用绑了重要东西的号。
- 不要高频群发、不要自动化加好友、不要做营销行为 —— 这些比注入本身更容易触发风控。
- `send_interval` 默认 0.3 秒，别调到 0。

**做不到的**：任何声称「绝对不封号」的注入方案都在骗人。

---

## 2. 管理员权限

注入 DLL、修改微信进程内存都需要管理员权限。这意味着：

- `start.bat` 必须以管理员身份运行
- 在这个窗口里跑起来的 Python 进程，**同样拥有管理员权限**

所以：不要在这个进程里跑来源不明的第三方插件，也不要让 AstrBot 的 agent 随便执行命令。

---

## 3. AstrBot agent 的权限面

这是最容易被忽略的一条。

如果你的 AstrBot 开了以下能力：

- 代码执行 / shell 工具
- 文件读写工具
- 浏览器 / 网页访问

那么**任何能给这个小号发消息的人**，理论上都能通过提示注入让 agent 在你的电脑上执行操作。而这个 Python 进程是管理员权限。

**必须做的**：

```jsonc
// config.json
"allowed_wxids": ["wxid_你的主号"]
```

白名单为空时，日志会明确警告 `未启用(所有人可用)`。

注意：群聊消息也会推给 AstrBot（为了让群聊上下文完整），所以如果小号在群里，**白名单要按发送者 wxid 过滤** —— 本项目的 `_passes_whitelist()` 就是这么做的，但群成员多的时候仍然建议单独建一个小号，只加必要的人。

---

## 4. 落盘的数据

运行时会在这几个位置留下数据，**都已在 `.gitignore` 里**：

| 文件 / 目录 | 内容 | 敏感度 |
| --- | --- | --- |
| `config.json` | 你的 wxid 白名单、AstrBot 地址 | 中 |
| `wxid_map.json` | wxid ↔ OneBot id 的映射，等于一份联系人片段 | **高** |
| `ready.json` | 当前登录的 wxid、昵称 | 中 |
| `logs/bridge.log` | 消息内容、发送目标、API 参数 | **高** |
| `patch_audit/*.jsonl` | 进程内存地址、改写记录、页保护前后值 | 低（但别提交） |
| `%TEMP%\wxhook_img_*` 等 | 收发的图片和文件副本 | **高** |

公开仓库、提 issue、发日志之前，**先脱敏**：把 `wxid_xxx` 换成 `wxid_示例`，群名和昵称删掉。

---

## 5. 版本与生命周期

- 上游支持 3.9.x–4.1.x，但本仓库只在 3.9.5.81 上验证过。
- 服务端有版本门禁，需要**版本伪装 + x64→x32 补丁 + 特定扫码顺序**三件套一起上，成功率随腾讯策略变化。
- 补丁开着跑会明显提高微信崩溃率（约每小时一次）—— 换来的是能登录。过了门禁后可以 `require_patch_and_faker: false` 手动关掉。
- 上游 `wxhook` 的维护状态不归本项目控制。

换句话说：**这套东西随时可能整体作废**，不要把它部署在关键业务上。

---

## 6. 杀软拦截

`wxhook` 自带的 `faker.exe` / `start-wechat.exe` 会被 Windows Defender 反复判为威胁并查杀（事件查看器里能看到同一文件一天内被删三次）。

所以启动前必须给它们加排除，否则**微信进程根本起不来**：

```powershell
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\uv\cache"
Add-MpPreference -ExclusionProcess "faker.exe"
Add-MpPreference -ExclusionProcess "start-wechat.exe"
```

要清楚这意味着什么：**你是在告诉杀软“这两个未签名的二进制可以随便跑”**。它们确实会读写微信进程内存（这正是本项目的原理），所以这不是误报意义上的“假阳性”，而是你主动接受的风险。

只给 `wxhook\tools\` 和 uv 缓存目录加排除，不要排除整个盘。
