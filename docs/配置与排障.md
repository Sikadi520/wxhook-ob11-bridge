# 配置与排障

## 配置文件

启动前执行：

```bat
copy config.example.json config.json
```

`config.json` 已在 `.gitignore` 里 —— 它包含你的 wxid，不要提交。

> JSON 不支持注释，所以模板里用 `_` 开头的键当说明（`_astrbot_ob_url`、`_门禁` 等）。程序会忽略它们，删掉也无妨。

---

## 字段说明

### 连接

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `astrbot_ob_url` | `ws://127.0.0.1:6199/ws` | AstrBot `aiocqhttp` 适配器的地址。**必须带 `/ws`**，少了会 405。**省掉端口**（写 `ws://127.0.0.1/ws`）就自动探测 11229 / 6199，见下面[端口怎么选](#端口怎么选) |
| `ws_max_size` | `67108864` | WebSocket 单帧上限（字节）。`0` 或 `null` 表示不限。见[设计说明 3.1](设计说明.md#31-默认-1-mib-单帧上限会把连接掐掉) |

### 微信 · 登录门禁

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `faked_version` | `3.9.12.51` | 版本伪装目标。**必须和 `patch_x64_to_x32` 一起开**；留空会自动补成这个值 |
| `patch_x64_to_x32` | `true` | `x64→x32` 内存补丁。**过门禁的必需项之一**，但开着跑约每小时会崩一次（见[设计说明 7](设计说明.md#7-关于-x64--x32-内存补丁)） |
| `patch_max_sites` | `999` | 补丁最多打多少处。实测 30–40 处；填 0 或负数会被改成 999 |
| `require_patch_and_faker` | `true` | 组合开关检查。`false` = 桥接不干预你的选择（排障用） |
| `self_wxid` | `""` | 留空即可，登录后自动取 |
| `image_wait_seconds` | `8` | 等 DLL 把图片落盘的最长秒数。网慢/图大可调到 15 |

`faked_version` 和 `patch_x64_to_x32` 的关系不是"建议"，是**实测结论**：

| `faked_version` | `patch_x64_to_x32` | 结果 |
| --- | --- | --- |
| 空 | true | ❌ 版本过低，微信被关 |
| `3.9.12.51` | false | ❌ 版本过低，弹窗在扫码前 |
| `3.9.12.51` | true | ✅ 登录成功 |

所以 `options.normalize()` 在启动时会把"只开一半"补齐，并在日志里打：

```
WARNING  [配置自动修正] patch_x64_to_x32=false → 已改为 true。伪装和补丁必须同时开…
INFO     [配置] 要还原成你自己写的值,把这一段写回 config.json:
INFO     [配置]   "faked_version": "", "patch_x64_to_x32": false, "require_patch_and_faker": false
```

想彻底不管它，就把 `require_patch_and_faker` 设成 `false`。

### 权限

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `allowed_wxids` | `[]` | ⚠️ 白名单。**空 = 不限制**，务必填自己的主号。群聊按发送者 wxid 判定 |
| `bot_nicknames` | `["小助手"]` | 群里的 @ 昵称，用来在 `atuserlist` 缺失时兜底剥离 @ 前缀 |

### 节奏

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `buffer_seconds` | `2` | 文字消息合并窗口。调大 = 更省 token / 更慢；调小 = 更快 / 可能拆成多次请求 |
| `image_buffer_seconds` | `10` | 含图片的缓冲用更长窗口，让用户把图发完 |
| `send_interval` | `0.3` | 每条消息发送前的等待，防触发风控 |
| `group_image_reply` | `true` | 群里没被 @ 但发了图时，是否也唤醒一次（让她讲解图片） |

### 媒体

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `gif_as_emotion` | `true` | GIF 走表情通道（`sendCustomEmotion`），否则发出去是静态首帧 |
| `gif_emotion_max_mb` | `5` | 超过这个大小的 GIF 退回图片通道（微信表情有大小上限） |
| `send_file_keep_seconds` | `1800` | 发送后延迟删除源文件的秒数。**别调太小**，wxhook 是异步上传 |

### 日志

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `log_level` | `INFO` | `DEBUG` 会打印每一帧 WebSocket 内容，很吵 |

日志同时写一份到 `logs/bridge.log`（5 MB 轮转，保留 3 份），因为管理员窗口的输出普通权限工具读不到。wxhook 自己的 loguru 日志（`SUCCESS wechat version faked: …` 这类）也会以 `WXHOOK | …` 为前缀写进同一个文件。

## 端口怎么选

AstrBot 的 `aiocqhttp` 端口改过一次默认值，这是最常见的一小时黑洞：

| AstrBot 版本 | 默认端口 |
| --- | --- |
| 3.x | `11229` |
| 4.x（如 4.29.1） | `6199` |

`preflight.resolve_ob_url()` 的规则：

| `astrbot_ob_url` | 行为 |
| --- | --- |
| 写了端口 | 只用这个端口。写错了不偷偷换 —— 日志会明确说「端口上没有服务在监听」 |
| 没写端口 | 先试 11229，再试 6199；第一个在监听的胜出，日志打印实际用的端口 |

两个都在监听时优先 11229（照顾老部署），日志里会顺带提一句 6199 也在监听。

## 启动、停止与重启

**正确的停止顺序**：先 `Ctrl+C`，再手动退出微信。

`main.py` 的 `Ctrl+C` 处理不会调用 `wxhook` 的 `exit()`，所以微信通常会留在后台。直接重跑会撞端口，不过启动时会自动清理：

1. `taskkill /F /IM WeChat.exe`（只针对 3.9.x 的 `WeChat.exe`，不动 4.x 的 `Weixin.exe`）
2. 杀掉占用 `18999` 的残留桥接进程
3. 删掉 `wxhook/tools/wxhook.json`（端口账本），让端口从 `19001` 重新分配

第 3 步现在按**实际 import 到的 wxhook 目录**去删，不再只扫 uv 缓存 —— 用 `.venv` 或本地 `site-packages` 装的时候，以前会漏掉，表现是"端口莫名其妙变成 19002"，然后 `Exception: port occupied:19001`。

**重启电脑 = 整套重来**：双击 `start.bat`，会话还在的话不用重新扫码。

## 排障速查

### 启动自检（`[自检]` 开头的日志）

桥接启动时按顺序检查，全部只读、不启动任何东西。`start.bat` 会先单独跑一次
`--doctor`，不过就**不启动**：

```bat
uv run --with wxhook --with pymem --with websockets python main.py --doctor
```

| 检查项 | 失败时的日志 |
| --- | --- |
| **微信版本**（注册表 `Version` → FileVersion → 目录名） | `微信版本不对:已安装 3.9.12.55,wxhook 0.0.10 只认 3.9.5.81` |
| **待升级痕迹** | `[升级迹象] 出现暂存目录 [3.9.12.55]_tmp` / `NeedUpdateType=200` |
| 管理员权限 | `当前不是管理员:注入 DLL 会失败` |
| AstrBot 端口 | `连不上 AstrBot:… 没有端口在监听` |
| wxhook 三个工具文件 | `wxhook 的文件不完整: faker.exe 不存在(极可能被 Windows Defender 查杀)` |
| faker.exe 可读性 | `faker.exe 存在但读不出来(被实时保护拦了)` |
| 微信进程 | `微信已经在运行(pid=…)`（警告，会自动接管） |
| 端口账本 | `wxhook 上次用过的端口 19001 现在没人在听(上个进程异常退出)` |

三个工具文件的 SHA256 会写进日志，方便和对端对照。

### 微信版本是怎么判定的

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `HKCU\Software\Tencent\WeChat\Version` | DWORD，`0x63090551` → `3.9.5.81`（首字节减 `0x60`） |
| 2 | `WeChat.exe` 的 FileVersion | 注册表读不到时的兜底（用 `-LiteralPath`，方括号目录要用字面量） |
| 3 | 安装目录里的 `[x.y.z]` | 最后兜底；`_tmp` 目录**不算**已安装版本 |

**判定不了就报“判定不了”，绝不猜** —— 报个假版本比没检测更糟。

> 实测坑：`Get-ChildItem 'C:\WeChat\[3.9.5.81]'` 在 PowerShell 里会**静默返回 0 条**，
> 因为方括号被当成字符类。必须用 `-LiteralPath`。本项目用 Python 的 `os.scandir`
> 实现（天然按字面量），单测里把这个行为锁死了。

### 微信被自动升级

完整背景、实测时间线与「为什么网传三步无效」见
[README 的「微信会静默把自己升级掉」](../README.md#-微信会静默把自己升级掉)。

要记住的三件事：

1. 升级**不需要确认、不需要重启电脑**，运行中就能完成；
2. 重装 3.9.5.81 而不封锁，**只能撑 5–12 分钟**；
3. 封锁要拒 **`WD,AD,DC`**，三处路径都要盖到，路径以实际安装目录为准。

**封锁的实际效果（实测）**：写新文件 ✓、新建 `[x.y.z]` / `_tmp` ✓、
**改名/顶替已有版本目录 ✓**（这才是升级的关键一步）；删除已存在文件 ✗（仍可删，
因 DENY 只加在对象自身，删除权来自父目录的 `DELETE_CHILD`）。

> ⚠️ 写封锁命令时 **`$deny = "${env:USERNAME}:(WD,AD,DC)"`**，
> 不能写成 `"$env:USERNAME:..."` —— PowerShell 会把冒号当作变量名一部分，
> 展开后只剩 `(WD,AD,DC)`，icacls 报 `无效参数`。

### 现象对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `WinError 1225` / 远程计算机拒绝连接 | 端口上没有服务 | `astrbot_ob_url` 省掉端口让它自动探测，或改成 WebUI 里的实际端口 |
| `当前客户端版本过低` | 门禁 | 确认伪装 + 补丁同时开（会自动补），然后按两段式扫码 |
| `Exception: unknown error` | **微信被静默升级了**（最常见） | 跑 `--doctor` 看已安装版本；不对就重装 + 封锁，见 [README](../README.md#-微信会静默把自己升级掉) |
| `WinError 225` / `WinError 2` | `faker.exe` 被查杀 | 见 README 的[杀软（Defender）](../README.md#杀软defender) |
| `Exception: port occupied:19001` | 残留微信/注入进程占着端口 | 启动时会自动清；仍不行就手动退出微信再跑 |
| `x64->x32 补丁: 回读确认 0 处` | 没提权 / 版本不对 / `patch_max_sites` 太小 | 用管理员运行 `start.bat`；确认微信是 3.9.5.81 |
| `faker 返回 -1(失败)` | 伪装没生效 | 微信进程已退出 / 权限不足 / 目标版本号不支持 |
| `WinError 10043` | 端口被残留进程占用 | 脚本会自动清理；仍不行就手动退出微信再跑 |
| `HTTP 405` / `400` | WebSocket 路径不对 | 确认地址以 `/ws` 结尾 |
| 有「推送事件(成功)」但没回复 | AstrBot 侧问题 | 看 AstrBot 的 `backend.log`；常见是插件阻塞 |
| 回复很慢 | 插件阻塞或缓冲太长 | 先看 AstrBot 插件日志，再调 `buffer_seconds` |
| 一条消息都收不到，但发送正常 | 接收端口 18999 被占 | 看日志里有没有「已结束占用 18999 的残留桥接进程」 |
| 图片收不到 / 模型报 400 | 分块落盘被抓成原图 | 本仓库已按精确文件名 + 文件头校验，确认代码是最新的 |
| 文件发出去「发送中断」 | 源文件被提前删 | 调大 `send_file_keep_seconds` |
| 群里指令不生效 | @ 前缀没剥掉 | 配 `bot_nicknames`，见[设计说明 1](设计说明.md#1-群里的--分隔符不是空格) |
| 群里 @ 别人它也回 | 靠文本猜 @ | 确认 `atuserlist` 判定生效（日志里会有「群 @ 判定修正」） |
| 微信进程突然消失 | 崩溃 / 被关闭 | 看日志里的看门狗警告；补丁开着时每小时崩一次属预期，过门禁后考虑关掉（`require_patch_and_faker: false`） |

### 补丁审计

每个站点都会记一条 JSONL（`patch_audit/patch-*.jsonl`），现在是 schema=2：

| 字段 | 含义 |
| --- | --- |
| `status` | `verified` / `skipped_crash_site` / `skipped_changed_bytes` / `write_failed_protect` / `write_failed_reprotect` / `write_failed_other` / `verify_mismatch` … |
| `protect_before` / `protect_before_name` | 写之前的页保护（如 `0x02` = `READONLY`） |
| `page_unlocked` | 是否临时放开过写保护 |
| `protect_restored` | 是否已恢复原保护（`false` 会带 `restore_error`） |

以前只读页写不进去，全部变成 `GetLastError 998` 的 `write_failed`（一次能到 20 处）。现在写之前 `VirtualProtectEx`、写完在 `finally` 里恢复，所以 `write_failed_protect` 才代表"真的没写进去"。
